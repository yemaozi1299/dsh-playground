# 拆不拆的尺子：会有第二个需要独立演进的实现吗

用户第一次答"中英文切换"时选了"一个定义 + 多个实现"，方向错了。纠正后掌握了两条判据：换的是**做法**还是**取值**（本地 bash 与沙箱 bash 是做法不同，中英文只是换词表）；这个选择是**部署级**还是**运行期**（语言写进 yml 就等于"换语言要改配置重启"）。

**Evidence**：2026-10-13 的语言改造四处全部按判据改对，且 `cordis.yml` 一行未改——判据的可证伪点正好是"配置不用动"。

**Implications**：这是目前最值钱的一条认知。以后的课程可以直接把它当工具用，不必再从头讲"依赖倒置"；反过来，如果哪次他又想按"通用性"拆分，要立刻把尺子拿出来。
