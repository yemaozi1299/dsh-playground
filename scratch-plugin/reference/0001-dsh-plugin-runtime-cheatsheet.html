一、点一次发送之后发生了什么

我打字发送
  → 记下「用户说了这句话」
  → 把说明书（各插件 register 的）+ 历史打包，发给模型
  → 模型说：请调用 greet，参数 name=Ada
  → 跑我写的 execute，得到 Hello, Ada!
  → 把结果再发给模型
  → 模型用正常人话回复我

一轮「模型请求 + 它点名的工具」= 一个步骤；一次发送到模型不再调工具 = 一个回合。

二、三份东西，不许混

这一份谁写的谁看出问题时的表现
说明书（name / description / parameters）插件的 register模型模型从不调用这个工具
execute插件作者只有程序调用了，但结果不对
网页气泡界面我显示不对／刷新后消失或重现

口诀：先加工具，不要先改引擎。 网页看不见调用，先问「插件挂上了吗、说明书清楚吗」，不要先怀疑界面。

三、插件的五个阶段

PENDING（等依赖）→ LOADING（跑 apply）→ ACTIVE（在跑）→ UNLOADING → DISPOSED
                                   ↘ apply 报错 → FAILED
  • inject = ['tools']：停在 PENDING 等这些服务全部就绪（写 100 个就等 100 个）。
  • 通过 ctx 登记的工具 / 事件 / effect：插件卸载时自动撤销。
  • 框架不认识的资源（定时器、连接）用 ctx.effect(() => { …; return 清理函数 }) 交出去。
  • HMR = 杀旧插件 → 清注册 → 载入新代码 → 跑新 apply。

四、事件：四种模式

模式行为记法
emit广播，返回值被忽略（喊的人不等回话）参数会传给 on
bail第一个非空返回就短路有答案就停
serial监听者排队依次执行按顺序来
waterfall流水线；必须调 next()，否则后面收不到少一次 next 就断链

服务是点名调用（一对一），事件是广播（一对多）。

五、一条能力的三种角色

角色负责例子
定义抽象契约、Request 类型、清单abstract class ShellExecutor；Greeter
实现具体做法bash-local / pwsh-sandbox；RandomGreeter
消费只认定义，ctx.shell.run(...)tool-bash；my-plugin.ts

拆分的尺子：会有第二个需要独立演进的实现吗？会 → 抽抽象定义；不会 → 一个类写完。

放哪里的尺子：部署级决定放 yml（换实现）；每个用户、每次调用不同的放运行期参数。

一个组合只挂一个提供方。重复挂不报错，后挂的被静默忽略。

六、两份清单，以及打包之后多了什么

回答什么问题在哪
package.json（购物清单）允许引用哪些包workspace:^ = 用本仓库里的那份
cordis.patch.yml（启动清单）启动时挂哪些行、什么 config练习场里靠 --patch 叠加
组合包 dsh.bundle这个包贡献什么（一个 patch 层）hello-plugin/package.json
profile dsh.profile这套配置由哪些组合包、按什么顺序组成$DSH_HOME/profiles/demo

没有东西同时是组合包和 profile。

层顺序（生效配置 = 空根上逐层叠加）

1. profile 的 dsh.profile.bundles 里各组合包的 patch（按列表顺序）
2. profile 自己的 cordis.patch.yml
3. $DSH_HOME/cordis.patch.yml
4. 每个 --patch <path> overlay（按命令行顺序）

后应用的层按行胜出，并且 patch 替换整行 config，不是深合并：要覆盖一行，必须重述这一行需要的每个键。用户也能在他自己的 profile 里覆盖你的行，不需要改你的包。

七、命令备忘

# 环境
pnpm install
pnpm run typecheck
pnpm run build              # 第一次起 web 之前需要；之后改练习插件通常不用

# 带着练习插件起网页
pnpm dsh web --patch ./scratch-plugin/cordis.yml

# 只编译练习场（不写 lib/，沙箱里也能跑）
pnpm exec tsc -p scratch-plugin/tsconfig.json --noEmit

# 离线对照实验
node --import ./tmp/register-alias.mjs tmp/greeter-check.ts
node --import ./tmp/register-alias.mjs tmp/echo-adapter/check.ts
node --import ./tmp/register-alias.mjs tmp/echo-adapter/check-theirs.ts

# basic/publish：装进 demo profile（要在自己的终端跑）
pnpm dsh plugin --profile demo add ./hello-plugin
pnpm dsh --profile demo --dump-config
pnpm dsh --profile demo

八、文件地图与禁区

路径是什么能不能乱进
scratch-plugin/练习场随便改
packages/产品代码要改功能才进
docs/说明迷路时查
apps/启动入口很少改
vendor/拷进来的 Cordis 等不要改
packages/core/agent-loop/循环本身先别碰
Session 日志格式 / 版本存档格式先别碰
