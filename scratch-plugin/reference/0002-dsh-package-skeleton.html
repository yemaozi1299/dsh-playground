速查 0002 · 正规包骨架与账单

压缩过的知识点，不是课。要动手时看 lesson 0002。术语在 GLOSSARY.md，权威清单在 docs/cookbook/adding-a-package.zh.md。

一、目录长什么样

packages/<组>/<包>/          ← 只能两层，多一层少一层都错
  package.json              ① 身份：名字、入口、依赖
  tsconfig.json             ② 这个包自己的编译边界
  src/index.ts              ③ 插件本体：name / inject / apply
  tests/*.spec.ts           ④ 行为测试（不在 src 里）
  README.md / README.zh.md  ⑤ 包的契约，门禁查章节结构
  locale/en.json zh.json    ⑥ 界面展示名（可选）

练习场 → 正规包的对应：src/my-plugin.ts → src/index.ts；scratch-plugin/tsconfig.json → 包内 tsconfig.json；"没有" → package.json / tests/ / README。

二、package.json 的不变式（pnpm run constraints 逐条查）

字段必须是什么
name@deepseek-ai/dsh-<名>；experimental 组必须是 @deepseek-ai/dsh-experimental-<名>
version与根 package.json 完全一致（dsh 家族共用一个版本号）
private进了 PRIVATE_EXPERIMENTAL_PACKAGE_DIRECTORIES 就必须 true，且不能有 publishConfig；否则相反
typemodule
main / typeslib/index.js / lib/types/index.d.ts
exports["."]必须同时有 types: "./lib/types/index.d.ts" 和 default: "./lib/index.js"
files正好是 ["lib/index.js", "lib/types/**/*.d.ts"]（有 bin / locale / client 时按规则追加）
@deepseek-ai/cordis同时出现在 peerDependencies 和 devDependencies，两处范围一致（vendor → workspace:~）
其它 peer 依赖每个都在 devDependencies 里镜像一份；DSH 包用 workspace:*

报错会直接把正确列表打出来，照抄即可。

三、四处登记，少一处症状不同

登记处写什么少了的症状
package.json名字、入口、依赖目录只是文件夹；constraints 报错
tsconfig.host.json（或 tsconfig.client.json）的 references{ "path": "./packages/<组>/<包>" }，只加一个聚合不属于任何编译单元，typecheck 不检查它
tsconfig.base.json 的 paths分两种：包名 = @deepseek-ai/dsh-<目录名> 的由 gen-tsconfig-paths 写进生成区；其余（含所有 dsh-experimental-*）手写在 BEGIN generated package aliases 之前gen-tsconfig-paths 报 no alias maps …；源码解析掉到构建产物 lib/
启动清单（profile 或 --patch）一行 insert，name 指包名或 lib/index.js 绝对路径编译全过、测试全绿，网页里没有这个工具

生成器的判据就一句：name === '@deepseek-ai/dsh-' + 目录名（scripts/gen-tsconfig-paths.ts 的 collectPackageAliases）。目录 tool-todo ↔ 包名 dsh-tool-todo 能生成；目录 hello-greet ↔ 包名 dsh-experimental-hello-greet 生成不了。别名写错位置会漏，写重了会遮蔽，所以生成区那一行注释别动。

四、搬不搬的尺子

scratch-plugin/ + --patchpackages/
可见范围只有你、这台机器整个仓库、CI、（默认）npm 使用者
改动代价改完刷新编译 + 门禁 + 测试 + README 契约
判断句还在试、自己用、不确定会长期存在，别人或未来的你会依赖它

packages/experimental/ 下的包默认属于发布家族；要留在本地，就把目录写进 scripts/experimental-package-policy.ts 的 PRIVATE_EXPERIMENTAL_PACKAGE_DIRECTORIES，并在 manifest 里写 "private": true。两处必须一起改。

五、命令顺序

pnpm install                                             # 认下新目录
pnpm run gen-tsconfig-paths                              # 检查别名齐不齐：期望 "package aliases are current."
pnpm run constraints                                     # package.json 不变式（静默 = 通过）
pnpm exec tsc -b packages/<组>/<包>                       # 编译这个包 → lib/types/index.d.ts
pnpm run typecheck                                       # 全仓库口径（较慢，含构建）

# 真挂载（需要先构建出 lib/index.js，那是 main 指向的构建产物）
pnpm run build
pnpm dsh web --patch ./scratch-plugin/<你的>.patch.yml

为什么练习场能直读 src/*.ts、正规包要先 build：package.json 的入口指向 lib/index.js，那是构建产物；src 只有 tsx 读得动。

七、报错对照

报错里的关键词去改哪
no alias maps …; add a hand-written entry … named after something other than its directory包名与目录名不同（experimental 组必然如此）：在 tsconfig.base.json 生成区之前手写一行别名，结尾逗号别丢
must set "private": true / must not set "private": true私有清单与 manifest 两处要对齐
version must match root version抄根 package.json 的 version
files must be [...]照报错里给的列表写
must start with "@deepseek-ai/dsh-experimental-"改包名，experimental 组前缀是硬性的
@deepseek-ai/cordis must be a peerDependency / ranges must matchpeer 与 dev 两处都写，范围一致
spawn EPERM / esbuild在网页会话里跑了：换自己的终端

八、从正规包到组合包（多带一层清单）

包根/
  cordis.patch.yml      ← 这一层要挂的行（顶层数组；insert 下面才是行）
  package.json          ← 三处新增：
    "exports": { "./cordis.patch.yml": "./cordis.patch.yml", ... }
    "files":   ["lib/index.js", "cordis.patch.yml", "lib/types/**/*.d.ts"]
    "dsh":     { "bundle": { "patch": "./cordis.patch.yml" } }   ← 顶层，不在 exports 里
pnpm run constraints                                    # files 必须含那个 patch 文件，否则报 files must be [...]
pnpm dsh plugin --profile <名> add ./packages/<组>/<包>    # link: 记进 dependencies + 包名进 bundles
pnpm dsh --profile <名> --dump-config | Select-String '<包名>'   # 找 # == <包名> 那一层
pnpm dsh plugin --profile <名> remove <包名>              # 撤销（bundles 列表一起清）
看到的意思
declares no dsh.bundle — installed as a plain dependency, not a profile layer装上了但不会贡献层：manifest 少了 dsh.bundle。补上后要先 remove 再 add，否则依赖已存在、不会重新登记
dsh.bundle.patch 是字符串或字符串列表一个文件，或按列表顺序应用的多个文件
不装 profile 也想看效果--patch 指 lib/index.js 的绝对路径：包名解析不到时，路径永远能解析
