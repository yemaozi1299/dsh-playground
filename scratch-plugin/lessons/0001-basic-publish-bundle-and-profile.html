把 hello-plugin 装进 demo profile

教学工作区 lesson 0001 · 接你的第 8 课 C 之后，官方路径是 basic/publish · 约 15 分钟（不含等 pnpm）

这一节的胜利条件

在你自己的终端里，同一次启动里看到两样东西：

pnpm dsh --profile demo --dump-config   # 输出里有一层  # == dsh-hello-plugin
pnpm dsh --profile demo                 # 终端打印  [hello-plugin] plugin loaded!

看到这两样，basic/publish 就结了 —— 你也第一次有了一个不靠 --patch、能被 profile 记住的插件。

为什么现在做这个

你的 basic/、framework/、practice/ 三层都走完了，product 里那条能力缝你也能自己写（三个 greeter 文件 + echo 适配器）。整个官方路径上只剩 basic/publish 这一节没走完，而且你已经做到一半：hello-plugin/ 建好了、dsh plugin --profile demo add 跑过了、profile 目录也生成了。剩下的是把最后两条命令跑完，以及把这一节的两个概念真正分清。

知识 · 两个概念，两种 manifest

你已经很熟"两份清单"了：package.json 是购物清单（允许引用），cordis.patch.yml 是启动清单（真正挂上）。publish 这一节做的，是把这两样东西打包成一个别人能安装的东西。

组合包（bundle）profile
回答什么这个包贡献什么这套配置由哪些组合包按什么顺序组成
manifestdsh.bundle.patchdsh.profile.bundles
你在哪写它你的包里（hello-plugin/package.json）$DSH_HOME/profiles/demo/package.json，由 dsh plugin 维护
谁用它安装它的人pnpm dsh --profile demo 启动它的人

没有东西同时是两者。 你写的 hello-plugin 是组合包；~/.dsh/profiles/demo 是 profile。你刚才那条 add 命令，做的是"把组合包登记进 profile 的 bundles 列表"。

知识 · 层顺序，和一条容易踩的规则

1. dsh.profile.bundles 里各组合包的 patch（按列表顺序）
2. profile 自己的 cordis.patch.yml
3. $DSH_HOME/cordis.patch.yml
4. 每个 --patch <path>（按命令行顺序）

后应用的层按行胜出。但注意：patch 替换整行的 config，不是深合并。所以谁要覆盖你的那一行，必须把这一行需要的每个键都重述一遍 —— 这也是为什么组合包应该给"用户大概率会保留的默认值"，其余交给 schema。

动手

在你自己的终端（不是这个网页会话里 —— 沙箱会挡住 esbuild 子进程，报 spawn EPERM），仓库根目录下：

cd C:\QQQQQ\claudeCode\dsh-playground

# 1. 先只验证层，不启动
pnpm dsh --profile demo --dump-config

# 2. 真的启动
pnpm dsh --profile demo

第 1 条命令的输出很长，用搜索找 # == dsh-hello-plugin 这一行 —— 它就是"你的组合包贡献的那一层"的标记。第 2 条启动后，终端应该出现你写在 index.js 里的那句日志。

现象先查什么
dsh: command not found源码 checkout 用 pnpm dsh ...，不是裸 dsh（教程正文写的是已安装 CLI 的情形）。
--dump-config 里没有那一层看 ~/.dsh/profiles/demo/package.json：dsh.profile.bundles 里有没有 dsh-hello-plugin；再看这个包有没有 dsh.bundle 声明。少了 dsh.bundle 的包"仍然可以安装，但只作为普通依赖"，且不会激活任何层。
启动没打印日志确认 index.js 是具名导出 name + apply；服务类才用 export default，两者不能混。
spawn EPERM / esbuild 报错你在这个网页会话里跑了。换到自己的终端 —— 这是沙箱限制，不是代码问题。
