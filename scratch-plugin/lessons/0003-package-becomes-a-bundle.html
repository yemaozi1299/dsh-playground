让你的包自己带一层：从正规包到组合包

教学工作区 lesson 0003 · 接 lesson 0002 · 约 20 分钟 · 速查：速查 0002（第八节就是这一课）· 术语：GLOSSARY.md

这一节的胜利条件

现在的 hello-greet 只是“能编译”。这一节给它加一层启动清单，让你的 web profile 认下这一层，最后在网页里让模型真的调用 greet：

pnpm run constraints                  # 静默 = files 那一项已经改对
pnpm dsh --profile web --dump-config  # 出现一层  # == @deepseek-ai/dsh-experimental-hello-greet
pnpm dsh web                          # 网页里能选到 greet，并让它跟 Ada 打个招呼

三样都看到，你手里就有了同一个工具的两种挂法：练习场靠 --patch 指路径，正规包靠包自己声明的那一层。

为什么现在做这个

lesson 0002 结束时，包能编译，lib/index.js 也在，可网页里就是看不见 greet：第四处登记（启动清单）还没做。这条路你的 hello-plugin/ 在 lesson 0001 已经走过一次，区别在于那次是两个手写文件的最小包，这回是有编译边界、有依赖、还要过门禁的正规包。走到这一步，「组合包」和「profile」就接上了。

知识一 · 组合包 = 正规包 + 一层清单 + 一句声明

先看实物，打开你自己写过的那两个文件：

hello-plugin/package.json
  "files": ["index.js", "cordis.patch.yml"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }   ← 这一句让它成为组合包

hello-plugin/cordis.patch.yml
  - insert:
      - id: hello
        name: dsh-hello-plugin                             ← 这一层要挂的行

就这两样。没有 dsh.bundle 的包“仍然可以安装，但只是普通依赖”，不会贡献任何一层。这句话 lesson 0001 的表里就有，现在换你亲手在自己的包上写一遍。

练习场插件（scratch-plugin/）组合包（你的 hello-greet）
谁决定挂哪一行你每次在命令行加 --patch包里的 cordis.patch.yml
谁记得它没人，关掉就没了profile 的 dsh.profile.bundles 列表
装给别人用做不到装进任意 profile：dsh plugin add

知识二 · dsh plugin add 到底做了三件事

pnpm dsh plugin --profile web add ./packages/experimental/hello-greet
  ① 在 profile 目录里跑 pnpm：本地目录用 link: 记进 dependencies
  ② 读这个包的 manifest，看有没有 dsh.bundle
       有 → 它贡献的那一层会被校验、并加进 dsh.profile.bundles 列表
       没有 → 打印一句警告，只当普通依赖装着（层不会出现）
  ③ 之后每次启动这个 profile，都会按 bundles 列表把那几层叠上去

那句警告值得记住原文，它就是漏写 dsh.bundle 时的样子：

dsh: warning: <包名> declares no dsh.bundle — installed as a plain dependency, not a profile layer

层的顺序还是你熟的那条：bundles 列表顺序 → profile 自己的 cordis.patch.yml → 各 --patch。所以以后想临时盖掉自己包里的某一行，照旧用 --patch，不用动包。

这一步会动到你每天都在用的 web profile。改动只有一条 link: 依赖和一个 bundles 条目，不复制代码，随时能撤：

pnpm dsh plugin --profile web remove @deepseek-ai/dsh-experimental-hello-greet

不想动 profile 的兜底做法在最后一步。

动手

在你自己的终端里做，仓库根目录。

1. 给包加一个 patch 文件

新建 packages/experimental/hello-greet/cordis.patch.yml：

- insert:
    - id: hello-greet
      name: '@deepseek-ai/dsh-experimental-hello-greet'

name 写自己的包名即可。启动时它从 profile 的 node_modules 解析，也就是你第 4 步装进去的那份。

2. manifest 加三处

  "exports": {
    ".": {
      "types": "./lib/types/index.d.ts",
      "default": "./lib/index.js"
    },
    "./cordis.patch.yml": "./cordis.patch.yml",        ← 新增：让 patch 文件可以被引用
    "./package.json": "./package.json"
  },
  "files": [
    "lib/index.js",
    "cordis.patch.yml",                                ← 新增：patch 文件要跟着发布
    "lib/types/**/*.d.ts"
  ],
  "dsh": {                                             ← 新增：声明"我贡献一层"
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  },

dsh 放在顶层，和 exports 同级，别塞进 exports 里。三项缺哪一样，constraints 都会报 files must be [...]，报错里直接给出你该有的列表。

片段里的 ← 新增 只是标注，别抄进文件。删注释时把行尾的对齐空格一起删掉：pre-commit 的 whitespace (staged) 会拦行尾空白，实现就是 git diff --cached --check。

3. 先验证清单

pnpm run constraints           # 静默 = files 已经是正确的那三项

4. 装进 web profile

pnpm dsh plugin --profile web add ./packages/experimental/hello-greet

输出末尾不该出现 declares no dsh.bundle 那句警告。接着看 profile 记下了什么：

Get-Content "$env:USERPROFILE\.dsh\profiles\web\package.json"

dependencies 里应该多出一条 "@deepseek-ai/dsh-experimental-hello-greet": "link:C:/.../packages/experimental/hello-greet"，dsh.profile.bundles 末尾多出你的包名。

5. 看那一层，再启动

pnpm dsh --profile web --dump-config | Select-String 'hello-greet'
# 期望：出现  # == @deepseek-ai/dsh-experimental-hello-greet  这一段标记

pnpm dsh web

网页起来后，在对话框里说一句「用 greet 工具跟 Ada 打个招呼」。工具列表里能看到 greet，模型调用它并回了问候语，这一节就算过了。

6. 兜底：不想动 profile 的话

--patch 永远是最外一层，所以不装 profile 也能看效果，代价是每次启动都得带上它：

# scratch-plugin/greet.patch.yml
- insert:
    - id: hello-greet
      name: 'C:/QQQQQ/claudeCode/dsh-playground/packages/experimental/hello-greet/lib/index.js'

pnpm dsh web --patch ./scratch-plugin/greet.patch.yml

这里必须写 lib/index.js 的绝对路径：还没有谁的 node_modules 认得这个包名，解析不到。两种办法各试一遍，“什么时候能用包名、什么时候只能用路径”就清楚了。

检查你是否真的懂了

2. 包装进 profile 了，--dump-config 里却找不到你那一层。先怀疑哪一处？

3. 为什么 cordis.patch.yml 必须写进 files？

现象先查什么
装的时候打印 declares no dsh.bundle — installed as a plain dependencymanifest 顶层的 dsh.bundle.patch 没写，或者写进了 exports。补上后先 plugin remove 再 add，否则依赖已存在、不会重新登记。
constraints 报 files must be [...]照报错给的列表写。声明了 dsh.bundle 之后，patch 文件就是必备项。
--dump-config 里没有你那一层先看 profile 的 package.json：bundles 里有没有你的包名；再看 dsh.bundle.patch 的路径是不是相对包根的（./cordis.patch.yml）。
启动时报 patch 文件读不到 / YAML 错cordis.patch.yml 顶层必须是数组，insert 下面才是行；缩进用空格。
插件一直 PENDINGinject: ['tools'] 等的是工具注册表，确认 base 那一层先应用了。
工具在列表里，模型却不调用回到那三层看：说明书（name / description / parameters）写清楚了吗？那是 lesson 0001 的范围，跟挂载无关。

这一节之后

把三样贴回来：--dump-config 里你那一层的标题行、profile 的 bundles 列表、模型调用 greet 的那次结果（截图或文字都行）。我据此写 learning record 0011。之后再付那份账单：README 两节（Model Experience / Known Limitations）、tests/ 行为测试、locale/ 展示名，把它从“能挂上的包”变成“能交出去的包”。
