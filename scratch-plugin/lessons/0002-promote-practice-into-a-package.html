把练习搬成一个正规包：最小骨架

教学工作区 lesson 0002 · 接 basic/publish 之后 · 约 25 分钟（大半时间在等命令）· 速查在 速查 0002

这一节的胜利条件

把 greet 工具搬进 packages/experimental/hello-greet/，然后四条命令各自留下一样能看见的东西：

命令（在你自己的终端）留下什么
pnpm installworkspace 把这个新目录认成一个包
pnpm run gen-tsconfig-paths打印 package aliases are current.（别名登记齐了）
pnpm run constraints没有输出 = package.json 的硬性清单全过
pnpm exec tsc -b packages/experimental/hello-greetlib/types/index.d.ts 出现

四条都过了，你就有了第一个正规包——不是"更正式的练习场"，是仓库里一个别人也会编译、会被门禁检查的东西。

为什么现在做这个

basic/、framework/、practice/ 三层你都走完了，basic/publish 也在你自己的终端跑通了。整个官方路径上只剩这一块没实操过：正规包长什么样——它多出来的不是代码，是登记和账单。这也是你 MISSION.md 里那条"能判断一件事该停在 --patch，还是值得搬进 packages/"的直接练习。

知识一 · 先看实物，别先背名词

打开仓库里一个真包：packages/experimental/tool-agent-team/。它就是"一个工具一个包"的最小形态，而你练习场里每个文件在它里面都有对应位置：

真包里的文件干什么你练习场里的对应物
package.json包的身份：名字、入口指向 lib/index.js、依赖声明没有（练习场不是包）
tsconfig.json这个包自己的编译边界：rootDir: src、extends 根配置、references 它依赖的包scratch-plugin/tsconfig.json
src/index.ts插件本体：name / inject / applysrc/my-plugin.ts
tests/行为测试（也在这里，不在 src/__tests__/）没有
README.md / README.zh.md这个包的契约，门禁检查章节结构没有
locale/en.json / zh.json插件在界面上的展示名（可选）没有

前三个是"跑起来需要的"，后三个是"搬进产品要付的账"。这一节只做前三个。

知识二 · 四处登记，少一处症状各不同

你的包
 ├─ ① package.json                  → 它是谁、入口在哪、能引用谁
 ├─ ② tsconfig.host.json references → 它属于哪个编译单元（host / client 二选一）
 ├─ ③ tsconfig.base.json 的 paths   → 源码别名（谁代写，看下面的例外）
 └─ ④ 启动清单（profile 或 --patch） → 启动时真的挂上它
少登记哪一处你会看到什么
① package.json 没写好目录只是文件夹：没别名、没入口、pnpm run constraints 直接报错
② tsconfig.host.json 里没有它pnpm run typecheck 从不检查你的源码——代码写错了也没人告诉你
③ 别名没登记gen-tsconfig-paths 报 no alias maps …，而且源码解析会掉到构建产物 lib/ 上
④ 启动清单里没有它编译全过、测试全绿，但网页里根本没有这个工具

③ 有个例外：tsconfig.base.json 里的别名只有一部分是生成的。生成器的条件是「包名正好等于 @deepseek-ai/dsh-<目录名>」（目录 tool-todo ↔ 包名 dsh-tool-todo）。而 experimental 组的包名强制带 experimental- 前缀，永远对不上——所以所有 dsh-experimental-* 的别名都手写在 BEGIN generated package aliases 那一行之前。你这个包也一样，必须手写一行。

知识三 · 尺子：搬进 packages/ 是签合同，不是升级

scratch-plugin/ + --patchpackages/
谁看得见只有你，只在这台机器整个仓库，CI，以及（默认）npm 上的使用者
改代码的代价改完刷新就行编译、门禁、测试、README 契约都要跟上
什么时候选它试想法、自己用、还不确定确定要长期存在，别人（或未来的你）会依赖它

关键一条：packages/experimental/ 下的包默认属于发布家族，会随 dsh 一起发到 npm。想留在本地就得显式登记为私有——这正是这一节第 2 步那一行。剩下的账单长这样，今天只付前两行：

账单项目这节付
package.json 不变式 + 四处登记（含手写别名）✅ 今天
能被 tsc -b 编过（拿到 lib/types/index.d.ts）✅ 今天
README.md + README.zh.md（含 Model Experience、Known Limitations 两节）下一节
tests/ 行为测试（CI 覆盖率按文件 100%）下一节
locale/ 展示名、doc-sync / hygiene 门禁下一节

动手

全部在你自己的终端里做（这个网页会话的沙箱会挡住 tsx 的子进程）。工作目录：C:\QQQQQ\claudeCode\dsh-playground。

1. 建目录

packages/experimental/hello-greet/

名字有硬性前缀：experimental 组的包必须叫 @deepseek-ai/dsh-experimental-*，否则 constraints 会把包名打回来。

2. 先登记"这是私有的"（一行）

改 scripts/experimental-package-policy.ts：

export const PRIVATE_EXPERIMENTAL_PACKAGE_DIRECTORIES: readonly string[] = [
  'packages/experimental/hello-greet',
]

不加这一行、又写了 "private": true，constraints 会报 public experimental package must not set "private": true；反过来不加 private，这个玩具就会跟着 dsh 发布出去。两处必须一起改。

3. 四个文件

package.json（version 抄根 package.json 的，现在是 0.2.1-alpha.1）：

{
  "name": "@deepseek-ai/dsh-experimental-hello-greet",
  "description": "Practice greet tool promoted into a workspace package",
  "version": "0.2.1-alpha.1",
  "private": true,
  "repository": {
    "type": "git",
    "url": "git+https://github.com/deepseek-ai/deepseek-harness.git",
    "directory": "packages/experimental/hello-greet"
  },
  "type": "module",
  "main": "lib/index.js",
  "types": "lib/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./lib/types/index.d.ts",
      "default": "./lib/index.js"
    },
    "./package.json": "./package.json"
  },
  "files": [
    "lib/index.js",
    "lib/types/**/*.d.ts"
  ],
  "license": "MIT",
  "peerDependencies": {
    "@deepseek-ai/dsh-tools": "workspace:*",
    "@deepseek-ai/cordis": "workspace:~"
  },
  "devDependencies": {
    "@deepseek-ai/dsh-tools": "workspace:*",
    "@deepseek-ai/cordis": "workspace:~"
  }
}

这几行不是随便写的，pnpm run constraints 逐条检查：type 必须是 module；main 必须指 lib/index.js；exports["."] 必须同时给出 types 和 default；files 必须正好是这两项；@deepseek-ai/cordis 必须同时出现在 peerDependencies 和 devDependencies 且范围一致；每个 peer 依赖都要在 dev 里镜像一份。

tsconfig.json：

{
  "extends": "../../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "lib/types"
  },
  "include": ["src"],
  "references": [
    { "path": "../../../vendor/cordis" },
    { "path": "../../core/tools" }
  ]
}

src/index.ts——就是你练习场里那个 greet 工具，去掉 greeter / greetCounter 两个依赖，改成一个文件自足（拆分留给"真的有第二个实现"那一天）：

import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

/** 支持的问候语言。这份清单在这里拥有，类型从它推出。 */
const GREET_LANGUAGES = ['zh', 'en'] as const

type GreetLanguage = (typeof GREET_LANGUAGES)[number]

/** 一次问候请求。 */
interface GreetRequest {
  name: string
  language: GreetLanguage
}

/**
 * 按语言拼出问候语。
 * @param request - 名字与语言。
 * @returns 拼好的问候语。
 */
function greet(request: GreetRequest): string {
  return request.language === 'en' ? `Hello, ${request.name}!` : `你好，${request.name}！`
}

export const name = 'greet-tool'

/** 工具注册表就绪之前，这个插件停在 PENDING。 */
export const inject = ['tools']

/**
 * 注册 greet 工具。
 * @param ctx - 插件上下文。
 */
export function apply(ctx: Context): void {
  ctx.tools.register(
    defineTool({
      name: 'greet',
      description: 'Greet someone by name.',
      parameters: {
        name: {
          type: 'string',
          required: true,
          description: 'The name to greet',
        },
        language: {
          type: 'string',
          enum: [...GREET_LANGUAGES],
          description: 'Greeting language: zh or en. Defaults to zh.',
        },
      },
      output: {
        schema: { type: 'string' },
        render: (_args, value) => [{ type: 'text', text: value }],
      },
      async execute(args) {
        return greet({ name: args.name, language: args.language ?? 'zh' })
      },
    }),
  )
}

注意写法没变：函数插件用具名导出，default 是服务类的写法，两者不能混。搬运不改变行为，只改变它被谁检查。

4. 登记两处：编译单元 + 源码别名

（a）打开 tsconfig.host.json，在 references 里加一行（放在其它 ./packages/experimental/... 旁边即可）：

{ "path": "./packages/experimental/hello-greet" },

普通包只属于一个聚合：这里是 host。client 是给浏览器那一半用的，两个都加是错的。

（b）打开 tsconfig.base.json，在手写区（BEGIN generated package aliases 之前、其它 dsh-experimental-* 旁边）加一行——结尾逗号别丢，因为生成区紧跟在后面：

      "@deepseek-ai/dsh-experimental-hello-greet": ["./packages/experimental/hello-greet/src"],

5. 跑四条命令

pnpm install
pnpm run gen-tsconfig-paths
pnpm run constraints
pnpm exec tsc -b packages/experimental/hello-greet

# 看证据
Select-String -Path tsconfig.base.json -Pattern 'hello-greet'      # 你手写的那条别名
Test-Path packages/experimental/hello-greet/lib/types/index.d.ts   # True

gen-tsconfig-paths 的角色是检查别名齐不齐（期望输出 package aliases are current.），不是替你写这一条。

会撞上的一条报错，先知道就不慌：只做了（a）没做（b）时，它会打印

gen-tsconfig-paths: no alias maps @deepseek-ai/dsh-experimental-hello-greet; add a hand-written entry,
because a package named after something other than its directory cannot be generated.

报错自己给了原因和解法。"包名和目录名不同就无法生成"这句，就是上面 ③ 的规则。

tsc -b 第一次可能跑一两分钟（它顺带检查这个包引用的 vendor/cordis、core/tools）。没有输出就是成功。

6. 加时赛（可选）：让它真的挂上

到现在为止，这个包只是"能被编译"。要真的出现在网页里，还差两步：pnpm run build（tsdown 把 lib/types/index.js 打包成 lib/index.js，也就是 main 指的那个文件），然后写一个 patch：

# scratch-plugin/package-greet.patch.yml
- insert:
    - id: hello-greet
      name: 'C:/QQQQQ/claudeCode/dsh-playground/packages/experimental/hello-greet/lib/index.js'

pnpm dsh web --patch ./scratch-plugin/package-greet.patch.yml

用绝对路径是为了绕开"这个包还没被谁依赖、所以 node_modules 里没有它"的问题——练习场一直就是这么挂的。做完这一步，你就有"同一个工具，两条挂载路径"的完整对照了。不顺就跳过，下一节本来就要走这条。

检查你是否真的懂了

1. 包建好了，但你没把它加进 tsconfig.host.json 的 references。后果是？

2. 为什么 dsh-experimental-* 这些包的别名必须手写进 tsconfig.base.json？

3. 一个新建的 packages/experimental/xxx/ 包，你什么都没声明，它的默认身份是？

4. 练习场能用绝对路径直接指 src/*.ts，正规包却要先 pnpm run build。为什么？

卡住了看这里

现象先查什么
gen-tsconfig-paths 报 no alias maps …你的包名与目录名不同（experimental 组必然如此）。去 tsconfig.base.json 的手写区加一行别名，逗号别丢。
constraints 报 must set "private": true第 2 步那一行有没有加进 PRIVATE_EXPERIMENTAL_PACKAGE_DIRECTORIES（目录字符串要写全，含 packages/ 前缀）。
constraints 报 version must match root version把根 package.json 的 version 原样抄进你的包。
constraints 报 files must be [...]照上面那份写；多一项少一项都会报，报错里会直接给出正确列表。
constraints 报 must start with "@deepseek-ai/dsh-experimental-"experimental 组的包名前缀是硬性的。
tsc -b 报找不到 ../../../tsconfig.base.json目录层级必须是 packages/<组>/<包>，多一层少一层都会错。
test:coverage / CI 说你的包没测试正常，这一节还没做 tests/——那是下一节的账。
spawn EPERM / esbuild 报错你在这个网页会话里跑了。换到自己的终端。
