给包写 README：模型看见的东西，得写成合同

教学工作区 lesson 0004 · 接 lesson 0003 · 约 20 分钟 · 速查：速查 0003 · 术语：GLOSSARY.md

这一节的胜利条件

hello-greet 已经能挂进 web profile，仓库的门禁却还不认它：没有 README 的包会被直接点名。这一节把四条检查跑绿，README 才算交出去：

pnpm run verify-package-readme-summaries
pnpm run verify-package-readme-model-experience
pnpm run verify-package-readme-limitations
pnpm exec vitest run scripts/doc-standard.spec.ts

完整 doc-sync 还会红。中文对照（README.zh.md 与配对记录）和三份生成物是下一节的事，tests/ 更后面。

为什么现在做这个

门禁扫的是 packages/*/*/package.json，按目录逐个找 README。少了就报 missing package README，代码写得多好都不看。

README 在这个仓库里不是宣传页。它要回答三件事：别人怎么装、模型看见什么、哪些坑接手的人必须知道。中间那件由 Model Experience 一节回答，也是这一课真正要学的部分。

格式很啰嗦，我先按门禁核对了一份，放在 packages/experimental/hello-greet/README.md。你要做的是核对它、跑检查，再改一处。

知识一 · kind 由事实推出

lesson 0003 你给 manifest 加了 dsh.bundle.patch。这条事实把 README 的 kind 定成 package-bundle，也把模板定成 package-bundle.md。换成 package-reference，doc-standard.spec.ts 会判 kind must be package-bundle。

同一份检查还查三样结构：## Summary（不超过 100 词）、## Table of Contents、### Dev Note。少一样都红。

知识二 · Model Experience 三格

这一节是整份 README 里唯一必须贴着源码写的地方。三格各回答一个问题：

字段回答什么greet 的答案
What the model sees模型收到的字面内容工具名 greet、description、name 必填、language 的 enum、返回一段文本
Token effect每次请求固定花多少，调用再加多少schema 每次请求都发；一次调用多一条短结果
KV Cache effect它在可复用前缀里吗，什么改动会让旧缓存失效schema 在前缀里；增删改这个包都会换前缀；结果只追加

What the model sees 写模型收到的字面内容。不要写“用户可以问候”，要写工具名、description、每个参数的必填与 enum、返回什么。空话过不了门禁：每个条目至少要有一处具体东西，反引号里的字段名、带标题的原文块、或工具目录的锚点链接，三样任选。

Token effect 分两笔：schema 是每次请求的固定成本；一次调用产生的结果是增量。

KV Cache effect 值得多写两句。工具 schema 和系统提示一起排在请求前部，构成可复用的前缀。增删改这个包，前缀就变了，之前缓存的条目不能复用。一次调用产生的结果加在前缀后面，只追加，不破坏前缀。

为什么不能写 None.：门禁支持一句话形式，但要求包名先登记进 SENTENCE_MODEL_EXPERIENCE，并写清理由。你的包自己注册工具，模型确实会看见东西，所以写结构化条目。

还有一个坑：条目标题里只要有 schema 这个词，门禁就要求链到 docs/tool-catalog.md 的锚点。greet 不在工具目录里（那份目录只从固定的一批插件生成），所以标题写 Greet tool。

知识三 · Known Limitations 写给接手的人

这一节写持久的约束：什么情况下会踩坑，踩了会看到什么。至少一条 - 开头的条目，门禁只查这一条。

不要把待办清单写进来。没有限制就登记进 NO_LIMITATIONS，别留一个空节。

动手

在你自己的终端里做，仓库根目录。

1. 对照源码核一遍

打开 README 和 src/index.ts，重点看三处：参数名、language 的 enum 与默认值、返回的文本。README 里写的每个字面量，源码里都要找得到。

2. 跑四条检查

pnpm run verify-package-readme-summaries
pnpm run verify-package-readme-model-experience
pnpm run verify-package-readme-limitations
pnpm exec vitest run scripts/doc-standard.spec.ts

前三条我在 2026-10-19 跑过，末尾分别是 … Summaries are within 100 words.、… all conform.、… all conform.。doc-standard.spec.ts 要起 vitest，得在你的终端跑；它扫全仓库的包 README，任何一份不合规都红。

顺带跑排版和链接：

pnpm run verify-md-wrap
pnpm run verify-md-links

README 里的相对链接从 README 所在目录算。回仓库根要 ../../..；少一层就落到 packages/docs/，报 target does not exist。

3. 让门禁咬你一口

把 #### KV Cache effect 里的 Cache 改成小写，再跑 pnpm run verify-package-readme-model-experience。报错会指出缺哪个字段。看完改回来，再跑一遍。

门禁逐字比对标题，不猜你的意思。这一步比读十遍规则有用。

4. 改一处你自己的话

至少改一条 Known Limitations，写你在 lesson 0003 真踩过或真担心的事。现成的一条：language 只认 zh 和 en，别的语言会被 enum 拒掉，现在还没写进限制里。改完再跑一遍三条 README 门禁。

检查你是否真的懂了

1. 这个包的 README 为什么必须写 kind: "package-bundle"？

2. 把工具的参数说明改了一个字，为什么会动到 KV 缓存？

3. 一个结构化的 Model Experience 条目，必须带哪三个 H4？

现象先查什么

这一节之后

把四条命令的末尾两三行贴回来，再贴你改的那条限制。下一节先补 README.zh.md 与配对记录，让 verify-translation-pairing 变绿；再清掉三份生成物：docs/config-catalog.md、agent-preset 里的 packages.md、docs/module-graph.md，用生成器重跑，不手改。再下一节写 tests/ 里的真组合测试。
